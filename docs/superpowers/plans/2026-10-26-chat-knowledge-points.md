# 聊天记录、社团知识与积分中心改进计划

> **For agentic workers:** Use superpowers:executing-plans to implement inline; use verification-before-completion before claiming completion.

**Goal:** 保留本次登录的聊天记录，补充其他社团知识文档，充实积分中心的真实数据展示。

**Architecture:** Vue/Pinia 管理按账号和社团隔离的会话，sessionStorage 支持刷新恢复，退出登录清除；Markdown 文档与可重复 SQL 迁移登记知识和积分演示数据；Java 继续提供积分查询与汇总，页面沿用 Element Plus 与现有 StatCard。

**Tech Stack:** Vue 3, Pinia, Element Plus, Spring Boot, MyBatis Plus, MySQL, FastAPI/Chroma。

**Spec:** 用户本次三项要求：切换页面保留聊天、退出可清空；编写其他社团文档；美化积分中心并补充数据。

## 设计约束

- 仅修改聊天、知识数据和积分相关功能，保留当前未提交修改和其他页面布局。
- 不把管理员虚构为获奖成员；无个人积分时诚实显示空状态，并提供社团动态。
- 新文档标注演示性质；待审批或驳回社团仅提供申请阶段指引。
- 不覆盖旧数据，不改已执行迁移；新增数据需可重复执行并验证积分总额。
- 积分切换社团需要按用户可访问社团设置查询范围，避免被默认首个社团的租户条件错误清空。
- 保留已有蓝色/白色设计系统，采用图标、原生条形图、表格与排行榜；不引入新的图表依赖。

## 已发现的问题

- ChatView 的 messages/sessionId 为组件 ref，页面卸载后丢失，切换社团也会直接清空。
- 积分中心对所有用户显示全社团列表，非管理员 SQL 又被默认社团租户过滤，可能把其他社团的数据误显示为空。
- 当前积分为0的管理员仍会被计算一个不存在的个人排名。
- 当前知识入库只识别运行目录相对文件，需要支持项目仓库中的文档路径。
- 实测发现话题关键词未覆盖“街舞社”“电竞社”“英语角”等知识问法，已补充规则和回归测试。
