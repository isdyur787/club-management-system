# 项目代码审查提示词

你是一名资深全栈工程师，拥有10年以上企业级系统开发经验。请对以下项目进行深度代码审查。

## 项目概述
这是一个社团管理系统，包含三个服务：
- 前端（SPA 单页应用）
- 后端服务（RESTful API）
- AI 微服务（RAG 问答 + Agent + 知识库管理）

三端协作：前端 → 后端 → AI 微服务

## 审查要求

### 重要原则
1. **逐文件、逐函数审查**，不要跳过任何文件
2. **不要给出"代码整体良好"等笼统评价**，只输出具体问题
3. 每个问题必须能落地到具体的代码行和运行场景
4. 区分"已确认的 bug"和"潜在风险"，分别标注

### 维度一：业务逻辑正确性
- API 端点的入参校验是否完善（空值、非法值、越界值）
- 业务流程的完整性（如报名→审核→通知，是否有遗漏环节）
- 数据一致性：写入和读取的数据结构是否匹配
- 缓存策略：缓存写入/读取/失效的逻辑是否闭环，缓存和源数据是否可能不一致
- 状态流转：业务对象的状态机是否有非法路径
- 边界场景：空数据、并发操作、超时后的重试是否会引发异常

### 维度二：异常处理与容错
- 所有外部调用（网络请求、数据库、第三方 API）是否有超时和重试机制
- 异常处理是否过于宽泛（捕获了所有异常但没有区分处理）
- 是否存在异常被静默吞掉的情况（catch 了但没做任何处理或记录）
- 降级逻辑：fallback 路径是否真的能正确覆盖主路径的失败场景
- 错误信息对用户是否友好，对开发者是否足够诊断问题

### 维度三：并发与资源管理
- 并发控制：共享资源（数据库连接、缓存、信号量）在并发场景下是否安全
- 资源泄漏：连接、文件句柄、线程、定时任务是否正确释放
- 异步模型：异步/同步混用是否得当，是否有阻塞主线程的操作
- 连接池/线程池配置是否合理，是否有耗尽风险

### 维度四：性能
- 是否有不必要的重复计算或重复 I/O
- 数据库查询效率（索引使用、N+1 问题、大数据量场景）
- 缓存命中率和失效策略是否合理
- 大数据量场景下的内存和响应时间表现
- 是否存在可以并行但目前是串行执行的独立操作

### 维度五：安全与健壮性
- 用户输入是否经过校验和清洗（注入攻击、XSS、路径穿越）
- 敏感信息（密钥、密码、Token）是否有泄露风险
- 权限控制：是否存在越权访问的可能
- 文件操作：上传/下载是否有类型和大小限制
- 日志是否记录了敏感数据

### 维度六：企业级工程实践
- 配置管理：硬编码的值是否应该提取为配置
- 代码组织：模块职责是否单一，是否有循环依赖
- 日志规范：关键操作是否有日志，日志级别是否恰当
- 可观测性：是否有健康检查、指标监控、链路追踪
- 代码可维护性：命名规范、注释质量、重复代码
- 部署与运维：服务启停是否优雅，配置是否环境隔离

## 输出格式

对每个发现的问题，按以下格式输出：

```
### [严重性] 问题标题
- **文件**: 具体文件路径
- **位置**: 函数名 / 大致行号范围
- **问题描述**: 在什么场景下会触发什么问题
- **影响**: 对用户/系统/数据的影响
- **修复建议**: 具体的修复方案（给出关键代码片段）
```

严重性分级：
- 🔴 **严重**：会导致功能异常、数据丢失、安全漏洞
- 🟡 **中等**：在特定条件下会出问题，或影响可维护性
- 🔵 **建议**：不紧急但可以提升代码质量的优化项

## 验证测试

审查完成后，请自行启动服务并进行功能验证：
1. 启动 AI 微服务（`ai-service/` 目录下运行）
2. 测试核心 API 端点的正常和异常场景
3. 验证你发现的问题是否确实存在
4. 对修复建议进行验证

最终按严重性排序输出问题清单，并附上验证测试的结果。
